# 任务完成与连续恢复修复

基于 Free AI 2.8.0，基线提交 `7e9ff1288835f522b0368ef0a3cf817a7f6c97c6`。

## 修复行为

- 已声明的检查被拒绝、未启动、超时或失败，均保留为未完成义务。模型只输出“完成”不能让它消失，无关命令成功不能替代它。
- 未完成计划不能靠删除步骤绕过；文件修改失败也会阻止完成，成功修复同一文件后可解除。
- 操作前先持久保存意图，文件写入前保存预期校验值。意外退出后可区分尚未核实的操作与普通待办；读回文件且校验一致时可恢复已经成功的写入记录。
- 每次继续继承累计编辑、最近观察、待核实操作和原检查。检查需在本轮重做；祖先记录不被改写。旧版 v1 记录会迁移为 v2，缺失祖先保留待核实状态。
- 对无法自动核实的中断，界面提供用户核实入口。它不向模型开放，也不豁免失败或未执行的检查。
- 聊天重开后保留这些状态。累计编辑与本轮改动分开，撤回按钮只处理当前运行自己的备份。

任务摘要有大小上限：保留最近 24 个编辑路径、16 条观察和16条检查详情，完整工具过程仍在每轮的 `events.jsonl`、`history.json` 和文件备份中。完成门槛检查程序已观察到的义务，不能证明模型发现了所有需求或把每个测试都正确标记为检查。没有待处理义务的只读问答可正常结束。

## 验证

2026-11-19，Windows、Python 3.12.3（含 Tcl/Tk），不下载模型、训练依赖或打包环境。

```powershell
python -E -s -B -X utf8 -m unittest discover -s development/tests -p 'test_*.py' -v
```

共 **200 项：197 通过、3 跳过、0 失败、0 错误**。跳过项为 Windows 当前账户不能创建符号链接的快照测试，以及依赖分发暂存目录的两项打包测试。未生成安装包。

新增完成与恢复用例使用脚本模拟模型决策，但实际创建、修改、读取文件，执行 Python 测试进程，并读取持久化记录。覆盖测试失败 → 修改 → 测试通过、两次续跑、检查拒绝/启动失败、步骤未完成、写入后突然中断、旧版祖先缺失和原记录不变。现有原生 Tk、SQLite 会话及客户端/训练端界面测试一并通过。

这验证执行层和恢复逻辑，**未验证真实语言模型的自主修复表现**。原始测试日志在本机 `development/reports/task-recovery-tests.txt`，机器可读摘要在同目录 JSON 文件；这些运行产物不进入仓库。
