# 项目快照、验收与恢复增强

2026-11-19，基于功能分支 `ac3cc53`。这轮完善现有聊天中的项目助手，不添加新页面、不下载模型或扩大默认运行依赖。

## 使用入口

每轮项目操作前后自动捕获有界文本快照。任务卡展开“详情”后可以查看改动、撤回文件修改，或打开“检查项目结果”输入本机测试命令。两种执行器共用同一快照模块，命令造成的新增、修改、删除也会记录。

检查失败后，结果保存到原聊天、任务卡和 SQLite。点“继续任务”会把检查结果作为历史证据交给模型；直接接着聊天也能看到该结果。修复后手动检查需重新运行，单条命令退出成功不会自动宣称全部需求完成。显示的是检查时的项目状态，重开对话、再次操作或撤回会使旧检查过期。

## 已修复的三个根因

- **长需求截断**：原来的 16,000 字节发送截断会静默遗漏尾部条件。新上限为 64 KiB UTF-8，启动前明确拒绝超限并保留草稿；范围内完整发送，脱敏全文存 `request.txt`，任务日记继续使用有界摘要。
- **中断疑点误解除**：原来所有请求共用 sessionId 身份，下一轮成功会误解除上一轮不确定操作。现在以 sessionId + runId 标识一次请求，原疑点保留到用户在最新卡核实。
- **旧卡续跑错位**：原来 Free AI 以选中卡作为父轮，但组件始终恢复已推进的同一会话。现在每条会话持久保存最新日记指针，并使用 OS 文件锁串行请求；旧卡解析到最新状态，旧版无法判定的分支拒绝猜测。人工确认不能从旧卡套用到新卡。

## 模块与范围

- `project_snapshot.py`：开始/结束快照、差异预览和冲突保护恢复。复用现有路径限制、目录固定、原子写入、凭据和忽略项过滤。每阶段最多 2,000 个 UTF-8 文件，每个 256 KiB；前后按内容去重共用 32 MiB。范围受限时不把未扫描路径推断成新增或删除。没有结束快照时不猜测命令改动；内置文件工具仍可使用自己的已验证备份。
- `project_verification.py`：复用内置命令执行器，无 shell 拼接，记录真实退出码、有界输出、耗时和运行前后文件指纹。只读权限拒绝执行，超时最多 120 秒，支持停止。指纹覆盖受支持项目文件；发生变化或无法完整扫描时，即使退出码为零也不标为通过。
- `project_chat.py` / `app_state.py`：统一接入两个执行器，保存快照指针和检查记录；通过/失效标记随聊天与历史同步，所有新入口留在原任务卡。

快照不覆盖模型、环境、私密文件、二进制、链接、数据库服务、网络操作或其他外部副作用，也不是整个项目的完整备份。它记录期间变化，无法证明每次变化由谁产生；任务期间用户编辑的文件也可能进入快照。撤回列表默认不选中，需用户明确选择文件。恢复只处理当前内容仍与结束版本匹配的文件，任务结束后的用户改动保留并提示冲突。重开时可只读已有前后归档恢复摘要，不会为了补记录重新采集当前现场。

## 验证结果

Windows、Python 3.12.3。最终全套 **265 项：262 通过、3 跳过、0 失败、0 错误**。跳过项目为当前账户无符号链接权限的一项测试，以及缺少分发暂存目录的两项打包检查。未创建新安装包。


修复前三个最小场景均使新增回归失败；修复后，同样 16,231 字节输入的尾部条件到达组件，中断后的问候保留疑点，A→B 后从 A 续跑得到 C 的实际父轮为 B。

真实 Tk 工作流测试包含：本机命令修改/新增/删除文件，手动检查失败，将报错送入后续模型请求，文件修复及命令通过，关闭并重开对话，撤回时保留用户后改内容，以及只读拦截。模型决策使用固定脚本。

另使用本机已有官方 Harness Windows EXE 运行扩展实验，模型端是本地固定 SSE 响应：

1. 实际 Python 测试先失败，官方组件写入修复，再运行测试通过。
2. 独立手动验收命令分别返回失败和通过，快照记录 `invoice.py` 改动。
3. 拒绝后无目标文件；真实取消后，同会话的无关回答仍为未完成且保留疑点，明确核实后恢复待验收。
4. 撤回组件产生的文件修改，字节恢复到原始失败版本，重跑测试重新失败，符合预期。
5. 扫描 35 个配置及日志文本，未发现实验密钥。

本机原始产物：`development/reports/workflow-tests-final.txt`、`development/reports/harness-experiment-eca_2d83/report.json`。报告不随应用分发。
