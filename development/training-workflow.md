# 训练成果验收与客户端使用

本阶段接通已有 SFT + LoRA 的产物使用流程。QLoRA、工具调用 SFT、DPO 和 GRPO 尚未在本阶段加入。

## 使用方法

1. 在训练工作台准备独立的训练环境和 Qwen3-0.6B 原始模型，检查训练数据后运行训练。
2. 打开“训练记录”，查看留出题的训练前后回答、验收结论和未通过的原因。
3. 对验收通过的新记录，点击“加入客户端模型”。程序复查原始记录与权重的 SHA-256，转换并保存一个独立的 GGUF LoRA 补丁。
4. 在客户端输入框的模型菜单中选择该训练成果。已打开的客户端会在展开菜单时发现新成果，无需切换到别的聊天页面。
5. 如果缺少配套的 Qwen3-0.6B GGUF 模型，在模型列表点击“下载配套模型”。发布成果不会偷偷下载或自动加载模型。

训练记录仍在 `portable_data/outputs`（或配置的数据根），发布的补丁位于模型根的 `trained` 文件夹。补丁与匹配基座组合运行；移除发布副本不会删除训练原始记录。移动整个 FreeAI 文件夹后，发布副本使用相对位置查找，不依赖原机器的源记录路径。

## 训练结束与验收通过

`summary.json` 中的 `completed: true` 只代表训练与前后生成流程结束。`acceptance_status` 单独记录效果验收结论。训练后出现更差的验证损失或检查题表现时，不会显示为验收通过。

两组留出题分别检查领域任务和基础能力。初始发布门槛为：

- 每组至少有 5 道前后都能评分的题，覆盖本组至少 80% 的题目。
- 每组训练后通过率至少 80%，且通过数不能低于训练前。
- 选中检查点的验证损失不得高于训练前，数值必须有限。
- 对照数据完整、题号与问题不重复，规则和参考答案有效。

这些阈值是项目的初始验收政策，不是通用智能水平的衡量。通过表示本批题达标，不一定有提升，也不能保证别的任务正确。当前不会自动执行数据集提供的代码或命令；代码任务的真实运行评分需要后续单独接入。

## 给检查题添加明确的评分规则

每行是独立 JSON。训练题和验证题仍使用原来的 `id / prompt / response` 字段。两类留出题可添加 `evaluation`：

```json
{"id":"check-domain-001","prompt":"只输出单词 ready。","response":"ready","evaluation":{"type":"exact"}}
{"id":"check-general-001","prompt":"只输出 JSON 对象，ok 的值为 true。","response":"{\"ok\":true}","evaluation":{"type":"json"}}
```

这些只是格式示例，不能当作充分的评测集。

- `exact`：仅统一 Unicode 表示、换行和首尾空白后，比较完整答案。不猜测不同表述是否等价。
- `json`：比较完整 JSON 结构和值，对象字段顺序不影响结果。布尔值和数字不同；重复键与非有限数值不接受。
- `manual` 或未填写：保留原文供人工查看，不自动判分。开放式问答应使用这一项，或另行建立明确的客观评分任务。

回答达到输出长度上限而没有正常结束，会作为截断结果记录。缺失生成结果、未知评分规则、覆盖不足等会显示需要核实。不会凭参考答案自动把自由问答改成精确匹配。

## 当前兼容范围

发布器只接受工作台当前生成的 Qwen3-0.6B、普通 LoRA、r=8、alpha=16、q_proj/v_proj、F32 补丁。它核对固定基础模型版本、张量形状、文件哈希及完整留出结果。不同模型、不同 LoRA 结构或不完整产物会被明确拒绝。

转换依据为已使用的 llama.cpp b11960 的 [LoRA 转换约定](https://github.com/ggml-org/llama.cpp/blob/b11960/convert_lora_to_gguf.py) 和 [适配器加载实现](https://github.com/ggml-org/llama.cpp/blob/b11960/src/llama-adapter.cpp)。当前格式范围很窄，因此可用标准库转换小补丁，不需要为发布步骤额外下载完整模型或训练框架。

旧训练记录缺少评估时绑定的文件哈希时，仍可查看前后回答，但不能直接发布。重新训练产生完整来源记录后才能加入客户端。不得手工修改对照答案或验收文件来代替真实的重新评估。
